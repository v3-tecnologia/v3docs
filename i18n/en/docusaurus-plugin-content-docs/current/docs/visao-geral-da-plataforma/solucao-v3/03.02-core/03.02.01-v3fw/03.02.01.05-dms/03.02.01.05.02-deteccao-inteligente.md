# Intelligent Driver Behavior Detection System (DMS)

## Overview

Our device uses an advanced system to monitor driver behavior in real time. This system works through an internal camera that captures images of the driver and a specialized library that analyzes these images to identify different behaviors.

## How Detection Works

### Image Analysis
The device camera continuously captures video frames of the driver. An external library analyzes these frames and extracts important information about:

- **Eye openness**: Monitors whether eyes are open, closed, or partially closed
- **Mouth position**: Detects whether the mouth is open (indicating possible yawning)
- **Gaze direction**: Identifies where the driver is looking
- **Head position**: Monitors head posture and orientation

### Detected Event Types

Based on this information, the system identifies the following behaviors:

| **Event** | **Description** |
|------------|---------------|
| **Gaze Fixation** | When the driver maintains a fixed gaze for too long |
| **Visual Distraction** | When the driver diverts their gaze from the road |
| **Posture Issues** | Excessive head tilt up/down or sideways |
| **Eye Closure** | Eyes closed for prolonged periods |
| **Drowsiness** | General signs of fatigue and decreased attention |
| **Eating** | Driver eating while driving |
| **Drinking** | Driver ingesting liquids |
| **Cell Phone Use** | Detection of phone near the ear |
| **Smoking** | Identification of smoking behavior |
| **Yawning** | Mouth opening characteristic of yawning |

### Event Grouping

Events are organized into three main categories:

| **Category** | **Included Events** | **Description** |
|---------------|----------------------|---------------|
| **Distraction** | Visual distraction, Gaze fixation, Posture issues | Behaviors that divert attention from driving |
| **Fatigue** | Eye closure, Yawning, Drowsiness | Fatigue signs that compromise safety |
| **Physical Distraction** | Cell phone use, Eating, Drinking, Smoking | Activities that occupy the hands or require physical attention |

## The Challenge: Too Many Unnecessary Alerts

The detection library is extremely sensitive and can identify behaviors several times per second. If we sent all these events directly to the monitoring center, we would have:

- Hundreds of alerts per minute
- Constant false positives
- Uncomfortable experience for the driver
- Monitoring system overload

## Our Solution: Intelligent Filtering System

To solve this problem, we developed a system that acts as an "intelligent filter" between raw detection and the sending of real alerts. This system is not just a sensitivity adjustment — it is a complex analysis that considers multiple factors.

## Specific Detection Rules

### Implemented Rules

The system processes **11 event types** through specific rules:

| **Event** | **Detection Function** | **Specific Conditions** |
|------------|------------------------|---------------------------|
| **Yawning** | `isYawning` | Vehicle in motion + valid mouth + yawning activity > threshold |
| **Visual Distraction** | `isGazeDistraction` | Vehicle in motion + diverted gaze + distraction time > threshold |
| **Gaze Fixation** | `isGazeFixation` | Specific conditions for prolonged gaze fixation |
| **Posture Issues (Pitch)** | `isPoseDistractionPitch` | Head tilt up/down > threshold |
| **Posture Issues (Yaw)** | `isPoseDistractionYaw` | Head rotation to sides > threshold |
| **Eye Closure** | `isEyeClosure` | Eye closure time > threshold |
| **Drowsiness** | `isDrowsiness` | Set of fatigue indicators |
| **Eating** | `isEating` | Eating activity detection |
| **Drinking** | `isDrinking` | Liquid ingestion detection |
| **Cell Phone Use** | `isOnPhone` | Phone near the ear |
| **Smoking** | `isSmoking` | Smoking behavior identification |

### Rule Processing System

#### 1. Common Basic Conditions

**Vehicle Movement Verification**
- Function: `isVehicleMoving(fact)`
- Condition: `current_speed >= minimum_moving_speed`
- Default minimum speed: **20 km/h** (configurable)
- Application: Many rules apply only when the vehicle is in motion

**Mouth Validation**
- Function: `isMouthValid(fact)`
- Verifies whether mouth detection is reliable
- Used mainly for yawning events

#### 2. Specific Rule Examples

**Yawning Rule (`isYawning`)**
```
IF (vehicle in motion) AND 
   (valid mouth) AND 
   (yawning activity > configured threshold)
THEN yawning event = true
```

**Visual Distraction Rule (`isGazeDistraction`)**
```
IF (vehicle in motion) AND 
   (gaze diverted from road) AND 
   (distraction time > configured threshold)
THEN distraction event = true
```

**Eye Closure Rule (`isEyeClosure`)**
```
IF (eye closure time > configured threshold)
THEN closure event = true
```

### Priority System

#### Priority Events (Immediate Processing)
The following events are **always processed immediately**:

1. **`YAWNING_EVENT`** - Yawning
2. **`EYE_CLOSURE_EVENT`** - Eye closure
3. **`ON_PHONE_EVENT`** - Cell phone use

**Priority Event Characteristics:**
- Completely ignore the time window
- Sent instantly when detected
- Update timestamp for future control
- If multiple priority events occur simultaneously, only the first in the list is sent

#### Regular Events (Frequency Control)
All other events go through the frequency control system:

- **`DROWSINESS_EVENT`** - Drowsiness
- **`GAZE_DISTRACTION_EVENT`** - Visual distraction
- **`GAZE_FIXATION_EVENT`** - Gaze fixation
- **`POSE_DISTRACTION_PITCH_EVENT`** - Posture issues (vertical)
- **`POSE_DISTRACTION_YAW_EVENT`** - Posture issues (horizontal)
- **`EATING_EVENT`** - Eating
- **`DRINKING_EVENT`** - Drinking
- **`SMOKING_EVENT`** - Smoking

### Frequency Control

#### Specific Parameters

**Time Window:**
- **Default duration**: 2 minutes
- **Application**: Non-priority events
- **Operation**: Event can only be sent again after 2 minutes from the last occurrence

#### Control Logic

```
FOR each detected non-priority event:
  IF (never detected before):
    - Send the event
    - Record current timestamp
  ELSE IF (elapsed time >= 2 minutes):
    - Send the event
    - Update timestamp
  ELSE:
    - Discard the event (still within time window)
```

## Processing Flow

### Step 1: Capture and Analysis
1. Camera continuously captures frames (10 FPS)
2. Library analyzes and generates raw events
3. System receives multiple events per second

### Step 2: Rule Application
1. **Context Creation**: Combines vision data + speed + configuration
2. **Execution of 11 Rules**: Each rule is evaluated with its specific conditions
3. **Event Filter**: Only events that passed the rules are considered

### Step 3: Priority System
1. **Priority Verification**: First search for priority events
2. **Priority Processing**: If found, only the priority event is sent
3. **Regular Processing**: If there are no priority events, process regular events

### Step 4: Frequency Control
1. **Priority Events**: Sent immediately
2. **Regular Events**: 2-minute window verification
3. **Final Decision**: Send or discard based on history

### Step 5: Buffer Management
The system maintains an intelligent buffer that:
- Temporarily stores events
- Discards older events when necessary
- Adapts to device memory availability

## Practical Examples

### Example 1: Yawning (Priority Event)
1. **Detection**: Driver yawns while driving at 50 km/h
2. **Rule Application**: `isYawning` → vehicle in motion ✓ + valid mouth ✓ + yawning detected ✓
3. **Priority Verification**: YAWNING_EVENT is priority ✓
4. **Result**: Alert sent immediately
5. **Protection**: Next yawn (if not priority) will only generate an alert after 2 minutes

### Example 2: Looking to the Side (Regular Event)
1. **Detection**: Driver looks to the side for 1 second
2. **Rule Application**: `isGazeDistraction` → insufficient time ✗
3. **Result**: Event discarded in the rules phase

### Example 3: Prolonged Distraction (Frequency Control)
1. **Detection**: Driver looks to the side for 5 seconds
2. **Rule Application**: `isGazeDistraction` → vehicle in motion ✓ + sufficient time ✓
3. **Priority Verification**: Not priority ✗
4. **Frequency Control**: Last distraction was 1 minute ago
5. **Result**: Event discarded (still within 2-minute window)

## Benefits of the New Approach

### For the Driver
- **Fewer Interruptions**: Alerts only when truly necessary
- **Greater Accuracy**: Drastic reduction of false positives
- **Improved Experience**: Less intrusive and more intelligent system

### For the Monitoring System
- **Relevant Data**: Only significant events are transmitted
- **Traffic Reduction**: Less transmitted data means lower cost and greater efficiency
- **Better Analysis**: Cleaner data enables more accurate analysis

### For Safety
- **Precise Detection**: Focus on truly dangerous behaviors
- **Appropriate Response**: Alerts proportional to risk level
- **Effective Prevention**: A system the driver takes seriously because it is accurate

## Configurability

### Adjustable Parameters

**Minimum Moving Speed:**
- Default: 20 km/h
- Purpose: Defines when the vehicle is "in motion"
- Impact: Affects most detection rules

**Time Window:**
- Default: 2 minutes
- Purpose: Controls frequency of non-priority events
- Configuration: Per event type if necessary

**Priority Event List:**
- Current: Drowsiness, Yawning, Eye closure, Cell phone use
- Flexibility: Can be modified according to safety policies

**Buffer Capacity:**
- Calculation: Based on FPS and memory availability
- Minimum: 50 events
- Adaptation: Dynamic according to available resources

**Detection Thresholds:**
- Specific to each rule (yawning, distraction, etc.)
- Calibratable as needed
- Balance between sensitivity and accuracy

## Conclusion

Our new approach transforms a "raw" detection system into an intelligent and practical solution. Through the application of 11 specific rules, a priority system with 4 critical events, and frequency control with a 2-minute window, we maintain high accuracy in detecting dangerous behaviors while eliminating excessive unnecessary alerts.

The result is a system that truly contributes to traffic safety, providing a balanced experience between effective monitoring and driver comfort.
